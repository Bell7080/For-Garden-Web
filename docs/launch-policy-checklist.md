# 출시 정책·확률 관리

홈페이지 `/legal`이 정책 문서의 단일 출처다. `/terms`, `/privacy`, `/probabilities`는 게임과 외부 스토어에서도 사용할 고정 주소다. 정책 페이지는 정적 HTML이라 게임 스크립트·공지 DB가 실패해도 읽을 수 있다. 문서 원문은 한국어이고 브라우저 번역을 막지 않는다.

## 수정·검토·시행

- 현재 판은 `2026-10-27-draft-4`다. 원고는 `scripts/legal-src/build-draft-4.py`, 문서 구성·자리표시자·출시 차단 항목·쿠폰 결정은 `docs/legal-documents-plan.md`가 갖는다.

- `content/legal/<version>.json`에서 초안을 관리한다. 현재 문서는 **시행 전 초안**이다. 시행 문구·날짜를 확인 없이 확정하지 않는다.
- 정책을 확정하거나 고지 내용을 변경할 때 새 버전 파일을 추가한다. 기존 버전과 연결된 확률 스냅샷은 수정하지 않는다. 현재 문서는 파일명 순서상 가장 마지막 버전이다.
- `probabilitySnapshot`에 해당 버전의 확률 JSON 경로를 명시한다. 새 게임 버전의 확률은 새 스냅샷·문서 버전으로 보존한다. `npm run sync:probabilities -- ../For-Garden`은 최신 초안의 버전명으로 스냅샷을 추출하고 그 초안의 참조만 갱신한다. 이전 버전의 스냅샷은 덮어쓰지 않으며, 최신 문서가 시행 중이면 새 초안을 먼저 만들도록 중단한다.
- `npm run generate:legal`이 고정 주소 및 `/legal/archive/<version>/<document>` 원문 보관본을 만든다. `npm run dev`와 `npm run build`에서도 실행된다. 생성 HTML을 수동 편집하지 않는다.
- 시행 시 `status: effective`, 실제 `effectiveDate`를 지정하고 가입·구매·수집 화면의 안내 및 필요한 동의와 함께 배포한다. 과거 동의 원문·버전은 보존한다. 웹 문서 게시만으로 동의가 성립하지 않는다.

## 운영자가 전달한 현재 계획 — 확정 정보 아님

- 운영 브랜드: **미정·재검토 중**. EnterGames는 동명 사용 발견으로 보류한 과거 후보다. 현재 홈페이지의 운영명으로 사용하지 않는다. 사업자등록 전이며 정식 상호·법적 운영주체·주소는 미확정이다. 등록된 회사나 법인으로 표시하지 않는다.
- 고객지원·개인정보 이메일: 아직 개설하지 않았다. 존재하지 않는 이메일이나 임의 주소를 문서에 넣지 않는다. 메일 외에 비공개 문의에서 실제 접수·답변 전달·권리 행사 처리가 가능한지도 확인한다.
- 1차 검토 지역: 한국·일본. 다음 검토 대상: 미국·대만 등. 이후 다른 지역으로 확대를 검토하되 일정·판매 가능 국가를 확정한 것은 아니다.
- 대만과 중국 본토는 별도 검토한다. 중국 본토를 절차가 간단한 지역으로 전제하지 않는다. 대만 역시 무절차 출시 지역으로 단정하지 않고 등급·판매·개인정보·세금·플랫폼 요건을 확인한다.
- 한국의 목표 등급: 12세 또는 15세 이용가 중 검토, 19세 방향은 지양. 공식 등급 확정 전에는 목표를 심사 결과처럼 표시하지 않는다. 일본·미국·대만의 등급과 스토어 설문은 각각 확인한다.
- 게임 이용 등급과 개인정보의 만 14세 기준을 혼동하지 않는다. 12세 이용가 선택 시 만 14세 미만 이용자의 수집 여부·법정대리인 동의 절차를 별도로 설계한다. 15세 이용가도 미성년자 구매 취소·보호자 동의 문제를 없애지 않는다.
- 다음 운영 준비: 전담 이메일 개설, 운영주체·사업자 표시 확정, 출시 국가·플랫폼 및 콘텐츠 기준 등급 검토. 지역별 법적 요건을 최신 공식 자료로 확인한 후 문서 시행과 수집·판매 기능을 연결한다.

## 운영자가 확정할 정보

- 사업자/개인 운영자 표시명, 사업자등록·통신판매 관련 표시 의무 해당 여부, 주소, 담당자와 비공개 고객지원/개인정보 연락처.
- 출시 국가, 플랫폼, 이용 등급·연령, 아동 대상 여부와 법정대리인 동의·미성년자 구매 취소 절차.
- 결제 주체·상품 조건·유무상 재화·유효기간·환불 경로·서비스 종료 시 잔액 처리, 디지털 콘텐츠 청약철회 고지·동의 요건. 일괄 환불 불가 문구를 사용하지 않는다.
- 개인정보 항목별 목적·법적 근거·필수/선택·보유기간·접근 권한·삭제 방식. Vercel/Supabase 계약 법인·지역·재위탁·백업 위치 및 국외 이전 근거·고지/동의.
- 문의 보유기간·답변 전달 경로·처리 기한. 공개 GitHub 이슈로 개인정보나 결제 정보를 받지 않는다.

## 실제 기능 검증 — 문서로 대체할 수 없음

- 사전예약의 기존 동의 버전은 `launch-notification-v1`이다. 문구·목적·기간이 바뀌면 DB 동의 버전도 새로 지정한다. 동의 시각·당시 원문과 연결되는지 검증한다.
- 문의 API는 동의 체크를 검사하지만 문구 버전·동의 시각·보유기간 및 철회 처리까지 갖춘 동의 이력은 추가 구현이 필요하다.
- 사전예약 알림 종료 후 30일 이내 파기 약속에 맞는 삭제 작업, 위탁사·백업·로그 처리, 신청 철회 절차를 구현·검증한다.
- 게임 기기 기록 초기화와 서버 계정 탈퇴를 분리한다. 앱 내부 및 외부 웹 삭제 요청 경로, 본인 확인, 법정 보관 분리와 실제 삭제를 검증한다.
- 광고성 정보 수신은 현재 받지 않는다. 도입 시 필수 신청 동의와 분리한 선택 동의·거부 경로·발신자·수신동의 확인 및 야간 광고 요건을 확인한다.
- 운영 제한 기간표·통지·이의 제기·복구·보상 기준을 확정한다. 커뮤니티 개설 시 신고·차단·삭제·저작권 신고·이의 절차를 추가한다.

## 확률 공개 검증

현재 공개 범위: 렐릭 연구 3종. 일반 슬롯, 10회 마지막 슬롯, SSR 천장, 픽업 확정 및 복합 상태와 개별 렐릭·수량형 재화 확률을 구분한다. 수량은 양끝 포함 균등 정수다. 같은 그룹의 천장 이월, SSR 획득 시 초기화, 픽업 실패 후 보장도 설명한다.

출시 전에 룬 생성·강화·특성 재설정, 지층 보상, 상품·보상 로테이션 등 모든 확률 요소를 목록화하고 유료 재화와의 연결 여부를 검토한다. 유료 상품과 연결된 조건부 확률·가변 확률·보장·복합 보상까지 공개 범위를 정하고 서버 운영값과 일치시켜야 한다. 개발 빌드 확률표를 상용 서버 확률의 검증 완료로 표시하지 않는다.

관련 기준은 실제 판매 국가·상품·플랫폼을 기준으로 최신 공식 자료와 전문가 검토를 거쳐 확정한다. 확인 출처: 개인정보보호위원회 https://www.pipc.go.kr/ · 국가법령정보센터 https://www.law.go.kr/ · 공정거래위원회 https://www.ftc.go.kr/ · 게임물관리위원회 https://www.grac.or.kr/ . 본 작업에서 외부 최신 법령 원문 대조는 수행하지 않았다.


## 출시 점검 20항목 (2026-10-29)

앱·웹 필수 점검 20항목의 항목별 현황과 이번 보강 내용은 `analysis/legal-a11y-checklist-2026-10-29.md`(프로젝트 파일)에 있다. 이 저장소에서 바뀐 것:

- **쿠키 정책(웹 전용)**: `/legal/cookies` 문서를 더했다. 홈페이지가 저장하는 값은 `fg-language`·`fg-theme`·`fg-storage-notice` 셋뿐이다. 앱은 브라우저 쿠키를 쓰지 않으므로 인게임에는 두지 않는다(응태 결정).
- **저장소 안내 띠**: `public/ui/storage-notice.js`가 모든 정적 페이지 아래에 한 번 뜬다. 행태 분석·광고 쿠키가 없어 선택 동의를 받는 배너가 아니라 안내·확인 띠다. **분석·광고 도구를 도입하는 순간 이 띠를 선택 동의(거부 가능, 기본 꺼짐)로 바꾸고 쿠키 정책을 먼저 고친다.**
- **저작물·외부 구성요소 고지** `/legal/licenses`: 글꼴·음원·SDK는 확인된 값으로, 이미지 원화의 제작 방식·권리자는 자리표시자다(응태 확인 필요).
- **문의 종류 「개인정보·삭제」(`privacy`)**: 홈페이지 문의 폼·`TICKET_CATEGORIES`·DB(`20261117000000_legal_privacy_deletion.sql`)에 더했다. 마이그레이션 적용 전에는 이 종류로 보내면 서버가 거절한다.
- **이메일 수신거부(18)**: 지금은 메일을 보내지 않는다. 출시 알림·광고성 메일을 보내기 전에 모든 메일 하단에 수신거부(출시 알림 신청 삭제) 링크를 넣고, 거부 처리 API(`preregister` 행 삭제)를 먼저 만든다. 광고성은 별도 선택 동의다(`/legal/marketing-consent`).
- **접근성(13~15)**: 의미 있는 이미지는 대체 텍스트, 장식 이미지는 빈 alt, 본문 바로가기·초점 표시·언어 선택 콤보박스 키보드 지원, 본문 색 대비 AA(최종 `--muted` #62646a)를 확인했다. 저장소 안내 띠도 키보드로 닫을 수 있다.
