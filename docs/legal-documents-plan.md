## 3. 문서가 약속했지만 아직 게임에 없는 것 (출시 차단)

- **계정 탈퇴**: `AccountApi.requestWithdrawal()`이 `unsupported`를 돌려준다. 유예·철회·법정 보관 분리·앱 밖 요청 처리까지 구현해야 탈퇴 안내가 참이 된다.
- **유료 젬/무료 젬 구분**: 지갑의 `gems`가 한 칸이다. 일부 사용 환불·서비스 종료 환불·5년 유효기간은 유료분을 따로 세야 계산된다.
- **구매 화면 표시**: 상품별 청약철회 제한 사유·유효기간·확률형 포함 여부를 구매 확인 창에 표시해야 철회 제한이 유효하다(전자상거래법 제17조 제6항). 지금은 프리미엄 안내의 「환불」 한 줄뿐이다.
- **확률 공개 범위**: `/probabilities`는 렐릭 연구 3종만 공개한다. 젬으로 직접·간접 살 수 있는 다른 우연 요소(룰렛, 상점 랜덤 룬, 지층 보상 등)를 조사해 포함 여부를 정해야 한다.
- **문의 유형 「계정·데이터 삭제」**: 탈퇴 안내가 이 유형을 가리킨다. 홈페이지 문의 폼에 유형이 없으면 더한다.
- **약관 동의 화면**: 웹 게시만으로 동의가 성립하지 않는다. 첫 실행·계정 생성 시 약관·처리방침 동의(버전 기록)를 받아야 한다.

## 4. 홈페이지 ↔ 게임 연동

| 게임 위치 | 홈페이지 주소 | 상태 |
| --- | --- | --- |
| 설정 > 지원 > 이용약관 | `/terms` | 있음 |
| 설정 > 지원 > 개인정보 처리방침 | `/privacy` | 있음 |
| 설정 > 지원 > 정책·확률 정보 | `/legal` (운영정책·환불·청소년·확률·사업자 정보 모두) | 이번에 추가 |
| 연구소 > 확률 정보 | 게임 안 표(`GachaRatesPopup`) — 홈페이지 `/probabilities`와 같은 값이어야 한다 | 있음(값 대조는 `npm run sync:probabilities`) |
| 설정 > 지원 > 문의하기 | 게임 안 문의 창 → 같은 `/api/support` 백엔드 | 있음 |
| 설정 > 계정 > 쿠폰 등록 | 게임 입력창 / iOS는 `/coupon` (아래 5절) | 구현됨 — 운영 DB 마이그레이션 적용 필요 |

게임은 고정 주소만 연다(`src/scenes/policyNavigation.ts`의 `PolicyPath`). 주소를 바꾸면 이전 주소를 리다이렉트로 남긴다 — 이미 배포된 앱이 옛 주소를 연다.
앱 셸(Capacitor)에서는 시스템 브라우저로 연다.

## 5. 쿠폰 등록 — 인게임 vs 홈페이지

현황: 서버(`For-Garden/supabase/migrations/20261017100000_operations_core.sql`, `…120000_coupon_reveal.sql`)에 `redeem_coupon(p_code)`가 있다.
로그인 사용자(`auth.uid()`) 기준, 공용/개별 코드, 기간·선착순, 계정당 1회, 10분 실패 5회 제한, 보상은 `grant_rewards`로 우편 지급. 어드민에서 발급·열람된다. **게임 안 입력 화면과 홈페이지 페이지는 둘 다 없다.**

| | 인게임 입력 | 홈페이지 입력 |
| --- | --- | --- |
| 이용자 경험 | 앱 안에서 바로, 로그인 그대로 | 앱을 나갔다 와야 함 |
| 본인 확인 | 기존 세션(추가 작업 없음) | 웹 로그인 또는 UID 입력 — 새 서버 함수 필요 |
| iOS 심사 | App Store 지침 3.1.1 위험(국내 다수 게임이 iOS만 웹으로 돌림) | 위험 없음 |
| 배포·홍보 | 코드 복사 후 앱 실행 | SNS·방송에서 링크로 바로 |
| 부정 대입 | 계정 단위 제한(이미 있음) | UID 방식이면 IP 단위 제한도 필요 |

**결정(응태): 혼합 — iOS만 홈페이지.** 구현 방식:

- 게임 설정 계정 칸의 「쿠폰 등록」 버튼이 입력창을 연다(`CouponPopup`). iOS 앱은 같은 버튼이 곧바로 홈페이지 `/coupon`을 연다.
- 홈페이지로 넘어갈 때 게임이 `create_coupon_ticket()`으로 15분짜리 연결 티켓을 받아 `/coupon#t=<티켓>`에 싣는다(`#` 뒤라 서버 로그·리퍼러에 남지 않는다).
  페이지는 `/api/coupon`(service role)으로 그 티켓의 UID·닉네임을 보여 주고 코드만 받는다. DB에는 티켓 해시만 남는다.
- UID만 받는 방식은 두지 않는다 — 남의 UID로 한정 코드를 소진시키거나 계정을 바꿔 가며 대입할 수 있다. 웹 로그인(OAuth)도 만들지 않았다 — 티켓이 그 몫을 한다.
- 게임·홈페이지 모두 같은 규칙 `private.redeem_coupon_for`를 지나고, 보상은 그 계정만 받는 **대상 우편**으로 간다.
  예전 `redeem_coupon`은 `player_assets`에 넣었는데 게임은 그 표를 읽지 않아 보상이 닿지 않았다 — 같은 마이그레이션(`20261106000000_coupon_mailbox.sql`)이 고쳤다.
- **운영 DB에는 아직 적용하지 않았다.** 적용 전에는 게임 버튼이 「서버에 연결되지 않음」으로, 홈페이지는 「등록하지 못했어요」로 끝난다.
