# Homepage UI rules

- Match the actual For-Garden game assets and `src/ui/{fonts,theme,glyphs,holo}.ts` in the sibling game checkout. Use the copied NEXON Kart 500/700/800 and FG Sans JP files; do not substitute approximate fonts. Minimum site text size is 12px at every breakpoint and in every locale; body text should generally be 15–16px.
- Site-owned browser controls must match the game. Do not add native select popups, default validation bubbles, unstyled checkboxes/radios, default dialogs, or default scrollbars. Use the shared controls in `src/ui/` and theme all new control states: idle, hover, focus, active, disabled, selected, error, open. Apply scrollbar styling to page, horizontal galleries, popups and future overflowing panels. Preserve standard scrolling and OS input accessibility.
- For language/options use the accessible custom picker: correct combobox/listbox roles, keyboard arrows/Home/End/Enter/Space, Escape/Tab/outside-click dismissal, visible focus, selected state and focus restoration. Never remove keyboard or screen reader support to change appearance. Honor reduced motion and forced colors.
- Draw UI SVG through `src/ui/icons.ts`: straight cuts, miter joins, flat silhouettes, currentColor, consistent strokes, no rounded leaf/emoji/text glyph substitutes. The globe/check/arrows follow the actual game's geometry. Mark decorative SVG aria-hidden and put accessible names on the associated controls.
- Keep the game's charcoal/gold/slanted-panel identity while retaining the website's spacing and artwork layout. Do not modify the game repository while implementing website changes.
- Verify ko/en/ja across phone/tablet/desktop, including open picker, modal scrollbars, checkbox focus, validation errors and no horizontal overflow. Run `npm test` and `npm run build`.
- Animated characters must use the real PuppetForge idle meshes, with static artwork fallback. Share parsed definitions but give each rendered character its own runtime. Lazy-load visible puppets, cap the shared renderer to 30fps, pause offscreen and in hidden tabs, and dispose observers/WebGL resources when components change. Reduced motion must leave the page fully readable and usable with static art.
- Character taps play the original hit clip with the game's speed 2.2 and strength 0.4, then return to idle after the exported duration divided by playback speed. Hold an active hit against repeated equal-priority taps, advance its lifetime only with the renderer, and support Enter/Space without intercepting touch scrolling. Never substitute a CSS shake for the mesh motion.
- Preserve native scroll, touch gestures and browser history. Use compositor-friendly, once-only scroll reveals and coalesce scroll updates with requestAnimationFrame; do not hijack wheel events, add perpetual offscreen loops, or introduce heavy animation frameworks for decorative effects. Button feedback follows the game's normal/primary press scales and durations. Keep page click effects short, bounded and non-interactive.
- Future community boards, feedback and support screens must reuse these shared controls, icons, motion and typography rules. Keep public content APIs separate from authenticated posting, moderation and private inquiries; do not invent a functioning board or claim receipt before a real backend confirms it.

- System/dark/light themes must cover page surfaces, text, inputs, menus, dialogs and scrollbars, preserve game art and use saved preferences before paint. Announcements use manually authored content for the site language, with original-language fallback and accurate lang attributes. Do not add automatic translation APIs, provider keys, generated-cache queries or translation retry UI. Keep the ordinary browser translation feature available.
- Vercel server functions use native Node ESM: relative server imports must include the emitted .js extension. npm run build includes test:api-runtime; keep that startup check independent from Vite/Vitest resolution so module-load failures cannot pass only frontend tests.

- Character introductions use `src/codex-data.json` from the game's relics, stories and locale catalogs. Keep actual names, quotes, specimen numbers, base stats and skill effects consistent with those sources; see `docs/character-archive.md`. Use original `public/assets/game/{factions,elements,roles,skills,currency}` symbols for identity, not invented SVG emblems. SD meshes follow the same idle/hit and visibility rules as full portraits. Keep character selection cards static and preserve keyboard focus and scroll position on selection. Wrap Japanese prose in narrow dossier/faction panels.
